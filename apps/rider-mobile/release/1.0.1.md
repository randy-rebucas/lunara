## Full changelog

### Cash collection

- **Cash payment card** on pickup and delivery tasks — amount, timing (pickup vs delivery), receipt code
- **"Cash collected"** action with API confirmation at the correct workflow step
- Collection gated on customer verification where required
- Shows collected status with amount and reference after completion

### Authentication

- **Redesigned login screen** with password and phone OTP modes
- **Twilio SMS OTP** for production phone sign-in
- Philippine mobile number validation
- Forgot password flow updated for new auth patterns

### Offline & sync

- **Offline cash collection** — queue collect-cash actions when offline; sync on reconnect
- **Pending sync indicators** on pickup/delivery when cash collection is queued
- **Auto-sync on app resume** — refresh pending queue and sync when app becomes active and online
- Optimistic task updates extended for payment-related offline actions

### Release engineering

- EAS production profile — Node 20, `autoIncrement`, Android app-bundle
- Platform-specific build scripts (`eas:build:ios`, `eas:build:android`)
- Monorepo environment loading from repo root in `app.config.js`
- EAS project ID linked in app config

## Build & submit commands

From `apps/rider-mobile`:

```bash
# Verify EAS env/secrets
eas secret:list

# Production builds (both platforms)
npm run eas:build
# or individually:
npm run eas:build:ios
npm run eas:build:android

# Submit latest builds to stores
eas submit --platform ios --profile production --latest
eas submit --platform android --profile production --latest
```

Monitor builds at [expo.dev/eas](https://expo.dev/eas).

## Pre-release checklist

### Configuration

- [ ] `EXPO_PUBLIC_API_URL` points to production API (not localhost)
- [ ] Twilio configured on API for reviewer OTP testing
- [ ] iOS APNs credentials configured (`eas credentials --platform ios`)
- [ ] Android signing key configured (`eas credentials --platform android`)
- [ ] Google Play service account JSON ready for `eas submit`

### Device verification

- [ ] Sign in with password and phone OTP
- [ ] Complete pickup task with cash collection at pickup
- [ ] Complete delivery task with cash collection at delivery
- [ ] Queue cash collection offline → verify sync on reconnect
- [ ] Verify pending-sync hint shows when cash action is queued
- [ ] Go online → accept task → complete full workflow

## Known limitations

- Public self-registration not supported — riders are onboarded by Lunara operations
- Push notifications require production EAS build + Firebase (not Expo Go)
- Store screenshots must be captured manually (no `store-assets` generator yet)
